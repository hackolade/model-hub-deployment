# Model Hub on Amazon EC2, with Terraform

This Terraform stack builds the deployment of the guide [Model Hub on Amazon EC2](https://hackolade.com/help/ModelHubonAmazonEC2.html): read the guide first. The stack makes the same choices, and the comments in `main.tf` name the step of the guide that each part follows.

**Before you start**, the Hackolade Helpdesk must have registered your hostname, as described in [Model Hub prerequisites](https://hackolade.com/help/ModelHubprerequisites.html). The license works only on that hostname, over HTTPS. This README uses `hck.example.com`; replace it with yours.

## What it creates

- A VPC with a public and a private subnet in each of two Availability Zones, and a NAT gateway.
- The security groups `hub-alb` (443 and 80 from `allowed_cidrs`), `hub-ec2` (3000 from `hub-alb`) and `hub-db` (5432 from `hub-ec2`).
- An RDS for PostgreSQL 17 database in the private subnets, with 7 days of automated backups.
- An Ubuntu 24.04 instance in a private subnet, with a 50 GiB gp3 disk, IMDSv2 only, and a role for Session Manager. There is no SSH access.
- Three Secrets Manager secrets, generated by Terraform: the master password of the database, the password of the `hck_hub` user, and the encryption key of the Model Hub.
- An internet-facing Application Load Balancer: HTTPS on port 443 to port 3000 of the instance, with health check `/ready`, and HTTP on port 80 redirected to HTTPS.
- With `route53_zone_id`: an ACM certificate validated in Route 53, and the alias record of the hostname.

At first boot, [user-data.sh](user-data.sh) does steps 4 to 6 of the guide: it installs Docker, creates the `hck_hub` user and database, writes `/opt/model-hub` with its `.env`, secrets, RDS certificate bundle and `docker-compose.yml`, and starts the Model Hub.

**Cost**: about USD 300 per month on demand in `eu-west-1`, mostly the instance (165), the database (55), the NAT gateway (35), the load balancer (20) and public IPv4 addresses (10), plus data transfer.

## Variables

| Variable | Default | Description |
| --- | --- | --- |
| `model_hub_version` | (required) | Tag of [hackolade/model-hub](https://hub.docker.com/r/hackolade/model-hub/tags) installed at first boot |
| `hostname` | `hck.example.com` | Hostname registered with the Hackolade Helpdesk |
| `certificate_arn` | `""` | ARN of an issued ACM certificate for the hostname |
| `route53_zone_id` | `""` | Route 53 public hosted zone of the hostname; the stack then requests the certificate and creates the DNS records |
| `allowed_cidrs` | `["0.0.0.0/0"]` | IP ranges allowed to reach the load balancer |
| `region` | `eu-west-1` | AWS region |
| `instance_type` | `m7i.xlarge` | EC2 instance type, at least 4 vCPUs |
| `db_instance_class` | `db.t4g.medium` | RDS instance class |

Set `certificate_arn`, `route53_zone_id`, or both.

## Deploy

You need Terraform 1.9 or later, and AWS credentials allowed to create the resources above. Create `terraform.tfvars`:

```hcl
model_hub_version = "<model-hub-version>"
hostname          = "hck.example.com"
route53_zone_id   = "<hosted-zone-id>" # or: certificate_arn = "<certificate-arn>"
allowed_cidrs     = ["203.0.113.0/24"]
```

Then run:

```bash
terraform init
terraform apply
```

If your DNS zone is not in Route 53, create a CNAME record from `hck.example.com` to the `alb_dns_name` output.

The first boot takes a few minutes. To follow it, connect with Session Manager and read its log:

```bash
aws ssm start-session --target <instance_id>
sudo tail -f /var/log/cloud-init-output.log
```

When `curl -f http://localhost:3000/ready` succeeds on the instance, open `https://hck.example.com` and continue with the [Model Hub configuration](https://hackolade.com/help/ModelHubconfiguration.html).

## Keep it safe and up to date

- The Terraform state holds the generated secrets: keep it in an encrypted backend with restricted access, such as an S3 bucket.
- Back up the encryption key secret (`encryption_key_secret_arn` output) with the database: without it, the Model Hub cannot read the configuration it stores there.
- The instance reads `model_hub_version` only at first boot. To upgrade, follow [Upgrade to new Model Hub version](https://hackolade.com/help/Installandstarttheserver.html#8-upgrade-to-new-model-hub-version) in `/opt/model-hub` on the instance.

## Destroy

```bash
terraform destroy
```

This deletes the database without a final snapshot, with its automated backups. Take a snapshot first if you want to keep the data. The secrets stay recoverable in Secrets Manager for 30 days.
